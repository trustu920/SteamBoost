# SteamBoost v1.0

把机械盘上的 Steam 游戏"借"到固态盘上玩：目录联接（Junction）让 Steam 全程无感——
它看到的永远是原来的路径，实际读写发生在固态盘上。玩完一键把差异镜像回写母本，再释放固态盘空间。

> 本文是 v1.0 的发布说明，发 Release 时直接复制这份内容。
> 包对应的校验值见文末。

## 下载与使用

1. 下载 `SteamBoost-v1.0-win64.zip`，**整个文件夹解压**到任意位置
   （别只把 exe 单独拷出来，它旁边的 `_internal\` 是 Qt 运行库）
2. 双击 `SteamBoost.exe` —— **不需要管理员权限**，全程普通权限运行
3. 首次使用：设置里选**母盘**（存游戏母本的机械盘）与**加速盘**（放下副本的固态盘）
   → 重新扫描 → 点卡片上的「加速到 SSD」

系统要求 Windows 10 / 11 + NTFS。
复制引擎优先使用你本机已安装的 FastCopy（`fcp.exe`），没装会自动回退 Windows 自带的 robocopy，
状态栏右下角始终显示当前**实际生效**的引擎，不会悄悄变慢。

## 这一版有什么

- **加速**：游戏复制到固态盘、原位置建立目录联接；母本先改名进同卷暂存区，任何一步失败都回滚
- **回写**：独立按钮，随时可点，**不改变加速状态** —— 把"数据不同步"的风险窗口从几天缩短到一次游戏
- **释放**：回写 → 严格校验 → 摘联接 → 母本回原位 → 删除缓存副本
- **隔离区而非删除**：回写时母盘多出来的文件只**移动**到 `<母盘>:\SteamBoostTrash\`，
  你确认游戏能正常运行之后，才决定删不删（也可以随时还原）
- **删除闸门**：全程序所有删除都走默认拒绝的闸门——路径白名单、拒绝盘根、拒绝 `\steamapps\` 下任何路径、
  拒绝系统与用户目录、拒绝把目录联接当普通目录删、执行前再复核一次；而且必须人工确认
- **修复向导**：启动自检识别加速/回写/释放中断、联接损坏、无主母本、无主缓存副本，
  逐条给出安全选项，绝不自动"清理"
- **审计日志**：每次加速/回写/释放/删除的路径、字节数、结果写入 `logs\operations.log`（按天滚动，保留 90 天）
- 浅色界面：虚拟化封面网格、可取消的任务队列（进度/速度/剩余时间）、系统托盘；另有命令行入口可脚本化

## 已知边界

- 校验用"大小 + 时间戳"，**内容变了但大小与时间戳都没变**的差异无法被发现
  （需要覆盖这种情况时，可在设置里开启 FastCopy 的 xxHash3 回读校验）
- **回写阶段不可取消**（设计如此，避免半途状态）
- 不要在加速状态下用 Steam 的"验证游戏文件完整性"或卸载/移动该游戏
- 反作弊网游请自行判断是否使用

## 环境与校验

Python 3.12.14 / PySide6 6.11.2 / Windows x64，**文件夹版（onedir）**。
单文件 exe 在部分系统上会被权限策略挡住（启动即报 `Could not create temporary directory!`），
换 PyInstaller 版本、换临时目录、指定 `--runtime-tmpdir` 都无效，属环境限制，所以发布文件夹版。
